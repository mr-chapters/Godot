# Project 03 — Final Challenge: Make Your Own Small Game

Use the skills from this course to design and build a small game with a clear beginning, gameplay loop, and ending. Choose a scope you can finish. A polished small game teaches more than an enormous unfinished idea.

## Choose a genre

Examples:
- Top-down survival
- Collect-and-escape puzzle
- Short platformer
- Arena game with waves of enemies
- Simple racing time trial
- Small exploration game

## Required features

Your project should include:
1. A main scene and at least one reusable scene.
2. Player input and a gameplay mechanic.
3. At least one signal connecting two systems.
4. A UI element showing meaningful game state.
5. A win condition and a failure or restart path.
6. Clear feedback such as sound, animation, or a message.
7. A README explaining controls and how to run the project.

Choose additional features only after the core loop works.

## Plan before coding

Write a short design document with:
- **Game idea:** one or two sentences.
- **Player goal:** what does the player try to achieve?
- **Core loop:** what does the player repeatedly do?
- **Controls:** which actions are available?
- **Scenes and systems:** what nodes or scripts are needed?
- **Win/failure conditions:** how does a run end?
- **Smallest playable version:** what is the minimum version you can finish?

## Milestones

- **Milestone 1:** a scene launches and the player can act.
- **Milestone 2:** the core mechanic works.
- **Milestone 3:** collision and game rules work.
- **Milestone 4:** UI and feedback are included.
- **Milestone 5:** win, failure, and restart work.
- **Milestone 6:** test, fix, document, and export.

## Quality checklist

- [ ] A new player can understand the objective.
- [ ] The controls work and are documented.
- [ ] The game can be completed or intentionally lost.
- [ ] No known blocker prevents normal play.
- [ ] Important scripts use clear names and focused functions.
- [ ] The README includes a screenshot or a description of the game.
- [ ] You can explain the important parts of your code without reading every line.

## Self-review questions

1. Which system did you design best, and why?
2. What bug took the longest to understand?
3. Where did you use a signal rather than a direct reference?
4. Which code would you improve if you had another day?
5. What would you learn next: animation, AI, shaders, 3D, multiplayer, or tools?

Finishing and reflecting on a small game is the goal. You do not need to add every possible feature.
